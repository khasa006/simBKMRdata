# Scientific validation audit for JOSS: simBKMRdata 0.2.2 and proposed 0.2.3 fixes

**Audit date:** November 12, 2026 (reviewed on the JOSS draft branch).  
**Scope:** Static examination of exported R functions, existing `testthat` tests, the original `simBKMR` scripts **read-only**, and the archived numerical-verification report. This audit does **not** independently rerun the original BKMR MCMC or the package on an R interpreter. GitHub Actions success verifies the repository's configured R package check, not every scientific property below.

## Findings and priority

| Priority | Component | Evidence | Interpretation/action |
| --- | --- | --- | --- |
| High | Gaussian subgroup simulation does not preserve empirical marginal SDs | `R/SimulateGroupGaussian.R` passes `sampCorr_mat` directly as `Sigma` in `MASS::mvrnorm()`; `sampSD` is required but unused | If an estimated Spearman correlation matrix is supplied, the generated Gaussian marginal variances are approximately 1, not the estimated `sampSD^2`. This is documented in source, but must be acknowledged as a methodological limitation. A 0.2.3 correction is now implemented on the draft branch and isolated in release PR #9: `diag(sampSD) %*% sampCorr_mat %*% diag(sampSD)`. Numerical results change for non-unit SDs. This treats supplied rank correlations as working Pearson correlations; exact rank targeting is a separate issue. CI/merge status must be confirmed. |
| High | Spearman correlation matrix used as latent normal covariance in Gamma generation | `estimate_mv_moments()` calculates `stats::cor(..., method='spearman')`; `generate_mvGamma_data()` passes that matrix to `MASS::mvrnorm()`, then applies `pnorm` and `qgamma` | Gamma marginals are obtained through a Gaussian-copula transform if the latent diagonal is one. But the resulting Spearman correlation is approximately `(6/pi)*asin(rho_latent/2)`, which differs from directly supplied `rho_latent` except at special values. A calibrated latent correlation matrix may be necessary when exact target rank correlations are required. |
| High | Missing outcome values and degenerate response statistics in threshold calculation | `calculate_pip_threshold()` computes `sd(y, na.rm=na.rm)` and `mean(y, na.rm=na.rm)` but `sampSize <- length(y)` | With `na.rm=TRUE`, missing response values are ignored for CV but counted in sample size. A mean of zero gives undefined/infinite CV; a constant outcome yields CV=0. Inputs are not validated. A 0.2.3 correction is now implemented on the draft branch and release PR #9: sample size is the number of nonmissing observed outcomes; invalid or degenerate inputs raise explicit errors. Complete-case arithmetic is unchanged; CI/merge status must be confirmed. |
| Medium | PIP function documentation overstates statistical guarantees | `R/CalculatePipThreshold.R` and `man/calculate_pip_threshold.Rd` claim nominal 5% test size and say the function invokes `nls` / Levenberg-Marquardt; the exported function actually evaluates *fixed coefficients* and never calls `nls` | Rewrite the documentation to state empirical simulation calibration, separate training/fitting of coefficients from formula evaluation, and explicitly deny formal Type I error guarantees. The reference placeholder `<......>` remains unfinished. |
| Medium | Gamma generator input validation incomplete | `generate_mvGamma_data()` checks length of shape and rate vectors only | No explicit guard for negative/nonfinite shape/rate, invalid sample size, non-square or nonpositive-definite latent correlation matrix, or diagonal values other than one. `pnorm` on latent normal variables with non-unit variances does not generate uniform marginal probabilities, so the specified Gamma marginals then need not hold. |
| Medium | Estimation routines use inconsistent missingness and correlation conventions | `estimate_mv_moments()` uses columnwise `na.rm=TRUE` for means/SD, pairwise-complete Spearman correlations, and total `nrow()` for skewness denominator | Incomplete data can produce incompatible effective sample sizes, and `.skewness()` sums missing terms without removal. Non-positive raw observations can also invalidate the Gamma parameter calculations. |
| Medium | Data redistribution provenance requires documentary confirmation | `R/data_metalExposChildren.R` describes real children's biomarker/IQ records with subject IDs and says CC BY 4.0 | Confirm explicit authorization, de-identification and license scope for **this derived dataset**. A source-line license assertion alone does not establish the rights or ethical basis to publicly redistribute the records. |
| Medium | Historical study-to-package correspondence not proven | `simBKMR/R/createSImulatedData_20240111.R` imports `lcmix` and calls `rmvgamma()`, while the package now uses its own latent Gaussian-to-Gamma transform. The dated threshold script defines the same rounded coefficient formula later exported by the package | Formula lineage is direct for the dynamic threshold. The first study used historical simulation scripts and a separate generator; equivalence to current `simBKMRdata` must not be asserted without further comparison. |
| Medium | JOSS research impact and open development | The separate `simBKMR` archive contains original scripts, saved PIP inputs, and checks, but not a full rerun; the CRAN package was released separately | An associated methodological publication is evidence of a research program, not necessarily evidence that the *current released software* was used externally. Provide verified adoption or reproducible usage records, and acknowledge JOSS's development-history screening risk. |

## Direct historical cross-check

1. `simBKMR/project2_dynamic_threshold/R_original/compareTestSize_20241211.R`, lines 138–171, defines/fits
   `A + (K-A)/(C+exp(-beta1*log2(CV)))^(beta2*log10(sampleSize))`.
2. That script, lines 210–215, uses `C=1.30460`, `beta1=0.59867`, `beta2=0.43565`. The exported package function evaluates the same expression when `A=0,K=1`.
3. `simBKMR/docs/NUMERICAL_VERIFICATION_2026-11-06.md` documents independently fitted estimates `1.304602101`, `0.598669409`, `0.435651200` from archived PIP outputs, and the rounded NHANES cutoff of approximately `0.646321317` for CV=15.18 and n=949. These are **saved-output numerical checks**, not the original MCMC rerun.
4. `simBKMR/R/createSImulatedData_20240111.R` uses `lcmix::rmvgamma()` with group-specific input parameters. The current package's `generate_mvGamma_data()` uses `MASS::mvrnorm()` followed by `pnorm` and `qgamma`. Identical scientific behavior is **not** established merely because both are multivariate Gamma generators.

## New package-level validation checks

`tests/testthat/test-joss-gamma-marginal-calibration.R` uses seeded stochastic draws with a diagonal latent correlation matrix, verifying Gamma empirical means/variances against theoretical expectations at a tolerance intended for Monte Carlo variability. It also checks the rank-dependence formula for a correlated two-variable case. These tests are *supporting diagnostics*, not evidence that every input condition works or that the historical manuscript simulation is reproduced.

## Decision before JOSS submission

**Not ready to declare JOSS submission-ready.** The two requested numerical corrections are implemented and covered by dedicated regression tests in a proposed 0.2.3 release branch, PR #9. They must pass the full package check before merging and publishing a new release. The distinction between Spearman rank correlation and a Gaussian working Pearson correlation remains; this correction does not purport to calibrate one to the other. Gamma input validation, example-data redistribution permission, actual historical software adoption, and complete MCMC reproduction remain separate limitations.

**Repositories:** This report was added only to the `simBKMRdata` draft branch; the `simBKMR` research repository was not changed.

### Newly confirmed remaining technical issues

| Priority | Function(s) | Specific code observation | Consequence and acceptance test |
| --- | --- | --- | --- |
| **Pre-release correction recommended (high)** | `generate_mvGamma_data()` | Only `length(shape_num)` and `length(rate_num)` are checked. No validation that `sampSize` is a positive integer, shape/rate vectors are finite and strictly positive, or latent `sampCorr_mat` is a square finite symmetric positive-semidefinite **correlation** matrix with diagonal one. | Invalid inputs may cause low-level numerical errors, warnings, non-finite output, or incorrect claimed Gamma marginals. Test 0/negative/noninteger/NA sample size, zero/negative/NA/Inf shape or rate, nonmatrix/nonsquare/dimension mismatch, diagonal not 1, asymmetric matrices, out-of-range off-diagonal elements and negative eigenvalues. Reject explicitly. |
| **Pre-release correction recommended (medium–high)** | `generate_mvGamma_data()` → `.mvGamma_fn()` | The generator passes the raw `MASS::mvrnorm()` result into `pnorm()` then a helper requiring `ncol()` and `nrow()`. `MASS::mvrnorm(n=1)` ordinarily returns a vector, so the single-observation case is not safely handled. | Normalize the draw to an `n × p` matrix, preserving column order, and assert that a one-row Gamma result has dimensions `1 × p`. Apply the same checks for one-dimensional input if that is an intended API case. |
| **Pre-release correction recommended (medium)** | `simulate_group_gamma()`, `simulate_group_data()` | Checks for group names only reject `NULL`; empty lists, empty/duplicate names, absent group-column names, mismatched dimensions, and repeated group labels are not comprehensively rejected. The generic wrapper also permits unvalidated Gaussian working covariance inputs. | Add malformed-group regression tests, use the same unique-name and column-name policy as `simulate_group_gaussian()`, and check consistent `p` before row binding. For the generic Gaussian path document that `sampCorr_mat` is used directly as covariance (unit marginal SD if a correlation matrix is supplied), rather than expecting the SD-preserving wrapper's behavior. |
| **Pre-release correction recommended (medium)** | `estimate_mv_moments()`, `.skewness()` | Means and SDs use per-column missing-value removal, correlations use pairwise-complete Spearman, yet skewness numerator/denominator use the unfiltered original vector and total `N`. | With NA exposure values, skewness can return NA despite usable observed data, effective sample sizes differ, and pairwise correlation estimates need not form a positive-semidefinite matrix for simulation. Define complete-case or per-variable policy and add reproducible tests. Do not silently change estimates in previously reported analyses. |
| **Pre-release correction recommended (medium)** | `estimate_mv_shape_rate()`, `calculate_stats_gamma()` | There are no explicit checks that input exposure concentrations are positive and finite for the Gamma model or that estimated shape/rate parameters are finite and positive; the group estimator does not check existence of its group column. | Document positive-data requirement; test zeros, negatives, missing/infinite values, constant columns and absent group column. Ensure clear errors rather than invalid Gamma output. |
| **Documented modeling limitation (not necessarily a blocking defect)** | `estimate_mv_moments()`, `simulate_group_gaussian()`, `generate_mvGamma_data()` | Upstream dependence is estimated using **Spearman**, but the Gaussian wrapper uses it as Pearson correlation and the Gamma generator uses it as a latent Gaussian correlation. | The realized sample's rank correlations need not equal the source data's rank correlations. For an ideal Gaussian copula, population Spearman `rho_S = (6/pi)asin(rho_latent/2)`. A separate calibrated option would be needed for exact rank-targeting and may be outside this release's scope; no exact-matching claim is permitted. |
| **Methodological warning** | `calculate_pip_threshold()` | The threshold evaluates fixed simulation-fitted coefficients; it does not control formal Type I error. It validates numeric input but arbitrary user-supplied coefficient combinations are not constrained to produce a threshold within [0,1]. | State calibrated-scope limits. Consider whether custom coefficients must yield [0,1] and test/validate accordingly; **do not change published default coefficients**. |

### Release-gating decisions

**Status: automated checks pass, but final methodological/input-domain review remains open.**

1. **Before recommending a stable 0.2.3 release:** Resolve or explicitly constrain/document the Gamma generator's invalid-input behavior and single-observation shape, with regression tests. The remaining grouped-estimation and missingness behavior should either be corrected with tests or narrowly described as unsupported input cases.
2. **For JOSS submission:** JOSS may accept a known, explicitly described limitation, but it should not be presented as a correctness guarantee. Whether missing-input handling is a blocking review issue is an author/editor decision; the clearly malformed-input cases deserve correction. Exact observed Spearman-correlation calibration is a *separate feature*, not an already implemented property.
3. Preserve the existing `metalExposChildren_df.rda` and `inst/extdata/metalExposChildren.csv` byte-for-byte. Author-reported 2025 permission remains documentary, not independently checked; confirm de-identification and public redistribution.
4. No new `v0.2.3` tag/release, CRAN submission, merge of PR #8/#9 or JOSS submission occurred in this review. Changes to simulation code should be tested in isolation on the development branch, then resubmitted for human scientific validation because the prior author approval covered the preceding revision.
