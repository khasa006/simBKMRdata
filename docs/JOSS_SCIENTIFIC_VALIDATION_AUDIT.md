# Scientific validation audit for JOSS: simBKMRdata 0.2.2

**Audit date:** November 12, 2026 (reviewed on the JOSS draft branch).  
**Scope:** Static examination of exported R functions, existing `testthat` tests, the original `simBKMR` scripts **read-only**, and the archived numerical-verification report. This audit does **not** independently rerun the original BKMR MCMC or the package on an R interpreter. GitHub Actions success verifies the repository's configured R package check, not every scientific property below.

## Findings and priority

| Priority | Component | Evidence | Interpretation/action |
| --- | --- | --- | --- |
| High | Gaussian subgroup simulation does not preserve empirical marginal SDs | `R/SimulateGroupGaussian.R` passes `sampCorr_mat` directly as `Sigma` in `MASS::mvrnorm()`; `sampSD` is required but unused | If an estimated Spearman correlation matrix is supplied, the generated Gaussian marginal variances are approximately 1, not the estimated `sampSD^2`. This is documented in source, but must be acknowledged as a methodological limitation. Correct behavior would require defining the intended covariance and possibly changing numerical results, so **not changed automatically**. |
| High | Spearman correlation matrix used as latent normal covariance in Gamma generation | `estimate_mv_moments()` calculates `stats::cor(..., method='spearman')`; `generate_mvGamma_data()` passes that matrix to `MASS::mvrnorm()`, then applies `pnorm` and `qgamma` | Gamma marginals are obtained through a Gaussian-copula transform if the latent diagonal is one. But the resulting Spearman correlation is approximately `(6/pi)*asin(rho_latent/2)`, which differs from directly supplied `rho_latent` except at special values. A calibrated latent correlation matrix may be necessary when exact target rank correlations are required. |
| High | Missing outcome values and degenerate response statistics in threshold calculation | `calculate_pip_threshold()` computes `sd(y, na.rm=na.rm)` and `mean(y, na.rm=na.rm)` but `sampSize <- length(y)` | With `na.rm=TRUE`, missing response values are ignored for CV but counted in sample size. A mean of zero gives undefined/infinite CV; a constant outcome yields CV=0. Inputs are not validated. Document the supported domain and decide how to handle these cases before a behavioral correction. |
| Medium | PIP function documentation overstates statistical guarantees | `R/CalculatePipThreshold.R` and `man/calculate_pip_threshold.Rd` claim nominal 5% test size and say the function invokes `nls` / Levenberg-Marquardt; the exported function actually evaluates *fixed coefficients* and never calls `nls` | Rewrite the documentation to state empirical simulation calibration, separate training/fitting of coefficients from formula evaluation, and explicitly deny formal Type I error guarantees. The reference placeholder `<......>` remains unfinished. |
| Medium | Gamma generator input validation incomplete | `generate_mvGamma_data()` checks length of shape and rate vectors only | No explicit guard for negative/nonfinite shape/rate, invalid sample size, non-square or nonpositive-definite latent correlation matrix, or diagonal values other than one. `pnorm` on latent normal variables with non-unit variances does not generate uniform marginal probabilities, so the specified Gamma marginals then need not hold. |
| Medium | Estimation routines use inconsistent missingness and correlation conventions | `estimate_mv_moments()` uses columnwise `na.rm=TRUE` for means/SD, pairwise-complete Spearman correlations, and total `nrow()` for skewness denominator | Incomplete data can produce incompatible effective sample sizes, and `.skewness()` sums missing terms without removal. Non-positive raw observations can also invalidate the Gamma parameter calculations. |
| Medium | Data redistribution provenance requires documentary confirmation | `R/data_metalExposChildren.R` describes real children's biomarker/IQ records with subject IDs and says CC BY 4.0 | Confirm explicit authorization, de-identification and license scope for **this derived dataset**. A source-line license assertion alone does not establish the rights or ethical basis to publicly redistribute the records. |
| Medium | Historical study-to-package correspondence not proven | `simBKMR/R/createSImulatedData_20240111.R` imports `lcmix` and calls `rmvgamma()`, while the package now uses its own latent Gaussian-to-Gamma transform. The dated threshold script defines the same rounded coefficient formula later exported by the package | Formula lineage is direct for the dynamic threshold. The first study used historical simulation scripts and a separate generator; equivalence to current `simBKMRdata` must not be asserted without further comparison. |
| Medium | JOSS research impact and open development | The separate `simBKMR` archive contains original scripts, saved PIP inputs, and checks, but not a full rerun; the CRAN package was released separately | An associated methodological publication is evidence of a research program, not necessarily evidence that the *current released software* was used externally. Provide verified adoption or reproducible usage records, and acknowledge JOSS's development-history screening risk. |

## Direct historical cross-check

1. `simBKMR/project2_dynamic_threshold/R_original/compareTestSize_20241211.R`, lines 138–171, defines/fits
   `A + (K-A)/(C+exp(-beta1*log2(CV)))^(beta2*log10(sampleSize))`.
2. That script, lines 210–215, uses `C=1.30460`, `beta1=0.59867`, `beta2=0.43565`. The exported package function evaluates the same expression when `A=0,K=1`.
3. `simBKMR/docs/NUMERICAL_VERIFICATION_2026-11-06.md` documents independently fitted estimates `1.304602101`, `0.598669409`, `0.435651200` from archived PIP outputs, and the rounded NHANES cutoff of approximately `0.646321317` for CV=15.18 and n=949. These are **saved-output numerical checks**, not the original MCMC rerun.
4. `simBKMR/R/createSImulatedData_20240111.R` uses `lcmix::rmvgamma()` with group-specific input parameters. The current package's `generate_mvGamma_data()` uses `MASS::mvrnorm()` followed by `pnorm` and `qgamma`. Identical scientific behavior is **not** established merely because both are multivariate Gamma generators.

## New package-level validation checks

`tests/testthat/test-joss-gamma-marginal-calibration.R` uses seeded stochastic draws with a diagonal latent correlation matrix, verifying Gamma empirical means/variances against theoretical expectations at a tolerance intended for Monte Carlo variability. It also checks the rank-dependence formula for a correlated two-variable case. These tests are *supporting diagnostics*, not evidence that every input condition works or that the historical manuscript simulation is reproduced.

## Decision before JOSS submission

**Not ready to declare scientific validation complete.** The software is released and testable, and threshold arithmetic has a direct match to archived work. However, the Gaussian dispersion issue, Spearman/latent Gaussian distinction, PIP missingness behavior, and distributional input validation deserve explicit decisions. At minimum, JOSS claims and package documentation must describe current behavior accurately. Changing those functions may be desirable, but it changes scientific output and requires author approval, dedicated regression tests, and a new versioned package release.

**Repositories:** This report was added only to the `simBKMRdata` draft branch; the `simBKMR` research repository was not changed.
